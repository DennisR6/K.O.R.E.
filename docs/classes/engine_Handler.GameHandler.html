    Class GameHandler

    Der zentrale Hub der Game Engine.

    Diese Klasse koordiniert den Spielzustand, das Rendering, die Physik und das Input-Handling. Sie fungiert als "Orchestrator", der alle Sub-Systeme (Physics, Entities, Systems) zusammenführt.

    Implements

    Erlaubt der Engine, den Game-Loop zu triggern.

    Implements

    Verarbeitet Maus-Interaktionen über das gesamte Spielfeld.

    finalizeTurnManual

    • finalizeTurnManual(): void

      Beendet den aktuellen Zug sofort und erzwingt den Endzustand.

      Diese Methode ist der "Hard-Reset":

      1. Sie teleportiert alle Objekte sofort an ihre berechneten Endpositionen.
      2. Sie stoppt alle laufenden Animationen im PlaybackSystem.
      3. Sie setzt den GameState direkt auf PLAYING_DONE.

      Nützlich für: "Animation überspringen" oder um sicherzustellen, dass alle Clients exakt die gleichen Daten haben (Sync).

      Returns void

    • getLocalInput(): | { actorId: string
      | number; angle: number; power: number }
      | null

      Die "Mathe-Küche": Berechnet Winkel und Kraft aus der Mausbewegung.

      Logik:

      • Power: Distanz zwischen Startpunkt und aktueller Maus (max. 100).
      • Angle: Wir addieren 180 Grad, da man "nach hinten" zieht, um "nach vorne" zu schießen (Billard-Prinzip).

      Returns { actorId: string | number; angle: number; power: number } | null

      Ein Objekt mit ID, Winkel und Kraft oder null, wenn die Bewegung zu kurz war.

    simulateTurn

    • simulateTurn(actorId: string | number, angle: number, power: number): TurnPacket

      Die "Glaskugel" der Engine: Berechnet einen kompletten Zug im Voraus.

      Erstellt eine Kopie der aktuellen Welt und lässt die Physik so lange laufen, bis alles wieder stillsteht. Der eigentliche Spielzustand bleibt unberührt.

      Parameters

        Wer führt den Zug aus?

      • angle: number

        In welche Richtung wird geschossen?

      • power: number

        Wie stark ist der Stoß?

      Returns TurnPacket

      Ein "Ticket" (TurnPacket), das genau beschreibt, was passieren wird.

    tick

    • tick(dt: number): void

      Der Core-Loop der Engine (Logic-Tick).

      Die Ausführung folgt einem strikten Layer-System:

      1. Pre-Tickers: System-nahe Logik (z.B. Pause-Menü, Overlays), die VOR dem Spiel gerendert/berechnet wird.
      2. Systems: Die eigentliche Spiel-Logik (ECS). Hier werden Entities verarbeitet.
      3. Post-Tickers: Hintergrund-Layer oder Effekte, die NACH der Hauptlogik kommen.

      Parameters

      • dt: number

        Delta Time (Zeit seit dem letzten Frame).

      Returns void

      Implementation of ITicker.tick
